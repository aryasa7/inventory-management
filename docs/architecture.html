Architecture Overview

Factory Inventory Management System

A full-stack demo application for tracking inventory, orders, demand, and spending across warehouses. Vue 3 single-page frontend, a FastAPI backend, and in-memory mock data loaded from JSON files — no database.

Tech Stack

Frontend

Vue 3 + Vite

  • vue 3.4 — Composition API
  • vue-router 4 — client-side routing
  • axios — HTTP client
  • Vite dev server on port 3000
Backend

FastAPI + Uvicorn

  • Python FastAPI app (server/main.py)
  • Pydantic models for request/response validation
  • CORS middleware (open, for local dev)
  • Uvicorn ASGI server on port 8001
Data

Mock JSON Data

  • No database — flat JSON files in server/data/
  • Loaded into memory once at startup (mock_data.py)
  • Inventory, orders, demand, backlog, spending, transactions
  • Changes are not persisted between restarts

Data Flow

1

Filters set in the UI

The FilterBar component drives shared state (Time Period, Warehouse, Category, Order Status) held in the useFilters composable, a singleton ref shared across the app.

2

View requests data

A view (e.g. Dashboard.vue, Inventory.vue) reads the current filters and calls a method on client/src/api.js, which builds query params and issues an axios GET request.

3

FastAPI filters in memory

The matching route in server/main.py applies shared helpers (apply_filters, filter_by_month) over the in-memory lists loaded from JSON — no query language, just Python list comprehensions.

4

Pydantic validates the response

Results are coerced through Pydantic response_model classes (e.g. InventoryItem, Order) before being serialized to JSON, guaranteeing a consistent shape back to the client.

5

Vue stores and derives

Raw results land in refs (allOrders, inventoryItems), and computed properties derive totals, chart data, and summaries — kept reactive to filter changes.
